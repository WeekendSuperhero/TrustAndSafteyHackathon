The problem

Five AI agents reconcile your ledger. One of them is padding invoices and writing perfectly reasonable notes. The usual safeguard is two disagreements and you are out. Over 200 simulated jobs against a sneaky rogue, that rule removed 1.44 honest agents per job for ordinary typos. A monitor that keeps accusing the wrong worker gets ignored, and then it protects nobody.

How it works

  1. Score, do not strike. Every agent carries a suspicion score. Agreeing with a partner lowers it. Disagreeing raises it, and more so when the same agent keeps pushing the total one way against different partners, or writes a note that reads like real LLM impostors.
  2. Test the suspect. An agent between 40 and 69 is paired next round with the lowest scoring agent. This is the canary check.
  3. Quarantine in silence. At 70 the agent is not told. It keeps getting work and receipts that say committed, while its numbers go to a shadow ledger that nobody uses.
  4. Let honest agents back in. Shadow answers are still scored. If the score falls under 40, the agent is reinstated.

The monitor never sees the true value. Every signal comes from what two agents posted.

Over 48 rounds the honeypot quarantines more honest agents at some point along the way (2.85 per job against 2.18), then reinstates most of them.

What still fools it

  • A patient rogue can keep a clean score and get picked as the trusted agent for canary checks.
  • Two agents who agree on the same fake number never trigger a disagreement.
  • Every simulation number comes from scripted agents. No live Claude games have been run yet.
  • The note weights were learned on game speech and have not been validated on real ledger notes.

If it were deployed and failed, the finance controller who owns the workflow is accountable. They would find out at the independent reconciliation against bank and vendor statements, which no agent touches.
